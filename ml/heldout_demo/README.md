# Synthetic material forecast demo

This folder produces an end-to-end **synthetic** ML demonstration for the four project categories in the SupplyChain AI prototype. Company records were not provided. Every training quantity is generated by fictional, versioned equations in `generate_and_train.py`; the model learns those equations plus bounded noise. The outputs are not a real plant forecast, approved engineering material take-off, or procurement instruction.

## Dataset plan

- **200 synthetic completed projects:** 50 for each project category.
- **Training/evaluation:** 40 training and 10 evaluation projects per category. Every material line from a project stays in that project's split.
- **Four separate prediction examples:** `PRED-BF-01`, `PRED-CV-01`, `PRED-EL-01`, and `PRED-CL-01`. They are never included in training, evaluation, tuning, or model selection.
- The count of 200 is a practical classroom/demo size, **not** a universal minimum and not evidence that real-world estimates would be accurate.

## How a draft is produced

1. `SCHEMA` describes the category-specific scope features and `MATERIALS` describes the eligible candidate materials and base units.
2. A completed-project scope is sampled from explicit fictional feature ranges. The category-specific `raw_quantities` equations create linked material quantity labels. Each quantity receives reproducible bounded variation of ±8% and discrete `ea` quantities are rounded.
3. A Random Forest regressor is fitted separately per category, with project scope as input and all category material quantities as outputs. A median-per-material baseline is evaluated alongside it.
4. For each of the four unseen prediction scopes, the category model predicts one quantity per eligible material. The draft includes a tree-spread P10/P90. These are **not calibrated confidence intervals**.
5. The resulting draft rows are synthetic estimates and still require engineering review. The language model does not create the candidate list or invent quantities.

## Files generated

Run the generator from this folder:

```powershell
python generate_and_train.py
```

It writes to `data/` by default. Use `--output-dir PATH` to choose another directory.

- `training_projects.csv` — 200 scope rows, split labels, provenance, generator version.
- `training_requirements.csv` — 2,400 project/candidate-material labels, including explicit not-required zeros, units, and provenance.
- `prediction_projects.csv` — the four held-out scope descriptions and structured inputs.
- `predicted_material_drafts.csv` — generated model outputs for those four examples.
- `evaluation_metrics.json` — per-material model MAE/WAPE versus the median baseline and library versions.
- `synthetic_material_models.joblib` — fitted model bundle for a future backend integration.

This is a standalone training/demo artifact. The current frontend still calls the separately maintained FastAPI service; that backend must load this bundle (or retrain it) and adapt its request/response schema before these predictions appear in the application.

## Important limitations

The generator's equations and candidate lists are fictional demo assumptions and have not been validated by a plant engineer. Strong evaluation scores only show that the model can reproduce this generator's assumptions. They do not establish that the estimates are correct for real projects. The feature ranges are not engineering limits. Before operational use, a qualified engineer must replace/review templates and equations using approved drawings/specifications; the model should then be retrained and independently evaluated on genuine, permitted project records. Never feed these outputs into live procurement decisions.

The generated P10/P90 values represent variation among trees in this fitted ensemble. They are not statistical guarantees or safety margins.
